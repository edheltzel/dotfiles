# config — application configs (stow package)

## Purpose

GNU Stow package holding XDG-compliant configuration for 20+ applications. Maps `config/.config/` → `~/.config/`.

## Ownership

Per-app config dirs under `.config/`: bat, borders, btop, fastfetch, gh, gh-changelog, gh-dash, ghostty, herdr, herdr-app, jj, karabiner, kitty, lazygit, leaderkey, markdownlint-cli2, raycast, starship, superfile, swiftkey, theme-switcher, wezterm, yazi, zed. Top-level files: `starship.toml`, `topgrade.toml`. Owns `config/.stow-local-ignore`. `ls config/.config` is the source of truth; this list rots.

## Local Contracts

- Stowed via `just stow config`; `config/.config/*` symlinks into `~/.config/`.
- `AGENTS.md` files are excluded from stow by `.stow-local-ignore` — they stay repo-only and are never symlinked into `~`.
- Never hardcode machine-specific or absolute home paths in app configs.
- Add a new app: drop its config under `.config/<app>/`, then `just stow config`.
- `herdr/` (the herdr multiplexer): config is tracked and stowed (`config.toml`, `plugins.json`, `customThemes.toml`, `agent-icons/`, `sounds/`, `themes/`). Runtime state is not: `.plugins.lock`, `herdr.sock.agent`, `release-notes.json`, `session.json`, `session-history.json`, `session-snapshots/`, and `plugins/config/` are gitignored and listed in `.stow-local-ignore`, because herdr rewrites them and a regular file at `~/.config/herdr` makes `stow --restow` abort the whole package. `plugins/github/` stays a tool-managed clone.
- `theme-switcher/`: `theme-switcher.sh` applies one of 14 themes across terminals, Neovim, bat, btop, starship, lazygit, Claude Code, herdr, gh-dash, tuxedo, yazi, and mdterm (`dark`/`light` only); the fish/zsh `theme` function wraps it. Per-app snippets live in `theme-switcher/<app>/<theme>.yml`; `current` holds the active name. See `theme-switcher/README.md`. Neovim's `eldritch-dusk` and `proxysoul` are local colorschemes (`neovim/.config/nvim/colors/<name>.lua`) on top of `eldritch.nvim`. `proxysoul` derives every app from proxySoul's kitty theme (`kitty/themes/proxysoul-main.conf`). Yazi has a flavor for every switcher theme (`tokyonight` → `tokyo-night`) and writes both `dark` and `light`. Eldritch Dusk text colors are darkened per hue (ANSI normal ≥4.5:1, bright ≥3:1); official neon Dusk accents stay for backgrounds/borders only, per upstream SPEC.md. tuxedo themes live in `tuxedo/themes/<theme>.toml` (stowed); its `config.toml` is app-owned and untracked, only `theme =` is rewritten.
- `rex/`: only `init.lua` is tracked. `install.sh` pre-creates `~/.config/rex` so Stow links the file instead of folding the whole dir. Its workflow `rex.action`s mirror the herdr popups on both `cmd+,` and `alt+,` leaders: `shift+b/d/f/t/s` open `but tui`, `gh dash`, `yazi`, `tuxedo`, or a shell in a 90% floating layer at the focused pane's cwd; `shift+v` splits Neovim right. Session switcher is leader `g`. Never bind keys the Empryo TUI uses (it can't remap): the tmux-style prefix is `ctrl+space` (not `ctrl+b`) and tab prev/next is `alt+shift+h/l` (not `alt+h/l`). Verify with `rex config check`, `rex keymap`, and `rex do <action> -s SESSION -b BLOCK`.
- `karabiner/` is legacy (LeaderKey replaced it); keep it buildable but do not extend it.
- `swiftkey/menu.yaml` is the SwiftKey launcher menu, converted from `leaderkey/config.json` with the same keys and order. Apps use `launch://`, folders and URLs use `open://`. Each top-level item opens on Hyper plus its key (`hotkey: "cmd+ctrl+alt+shift+<key>"`; SwiftKey has no `hyper` token). SwiftKey takes SF Symbols only, so emoji labels and app-bundle icons from LeaderKey were dropped or replaced; the LeaderKey file stays as the source to diff against.
- `superfile`: `theme/eldritch.toml` and `hotkeys.toml` are tracked (stow symlinks them into superfile's real, app-owned dir). `hotkeys.toml` is the upstream vim preset (vim nav: `-` parent, `enter` confirm, `m` select, `p` paste, `ctrl+c` quit, `q` close-panel). The bundled themes and `config.toml` (mode 600, private) stay untracked; the active-theme line is set live in `~/.config/superfile/config.toml`.
- `herdr-app` (the Herdr desktop app): only person-owned files are tracked: `keys.json`, `settings.json`, `themes/{proxysoul,eldritch,eldritch-dusk,dracula}.json`, `sounds/`, and the `mods/popup-*` + `mods/split-nvim` key launchers. `scripts/link-herdr-app.sh` links them into the app's real dir (the subtree is excluded from Stow). Install/bootstrap, `just stow config`, and `just update` call it; `just herdr-app` refreshes it alone. Conflicting personal files are backed up first. Cross-machine configuration travels through this repo, not herdr-core; after publishing, pull on the other machine and run `just herdr-app`. The app rewrites everything else there (`AGENTS.md`, `*.d.ts`, shipped mods and layouts, state) on every start, so never fold or track the whole dir. It also writes `gpui-kit.d.ts` and `jsconfig.json` into each tracked mod folder; `herdr-app/.gitignore` keeps them out. The app recreates a missing `keys.json`/`settings.json` with defaults within a second: replace one with its link by renaming a link over it (`ln -s … .tmp && mv -f .tmp keys.json`), not delete-then-stow. Its file watcher does not follow links: after editing a tracked file, `touch -h ~/.config/herdr-app/<path>` (or restart the app) to reload it. The app's own writes (Settings, zoom keys) keep the links. Mods can't import across folders, so each `popup-*/main.js` repeats the same launcher with its own `CMD`. Legacy leader shortcuts are two-stroke sequences: release Option+comma before the second stroke (for example Shift+S for the shell popup). `Cmd+/` shows loaded bindings; Absence from `installed.json` does not mean a personal mod is unavailable; test it with `herdr-app do mod.open --name <mod>`.
- Starship (`starship.toml` + `.config/starship/`): branch display is `${custom.gitbutler}` from vendored [starship-gitbutler](https://github.com/1stvamp/starship-gitbutler) (`gitbutler-branch.sh`, Apache-2.0). Keep `[git_branch]` disabled while that module is active, or `$all` will also print `gitbutler/workspace`. Local patches: `but status --json` (GitButler CLI 0.22 dropped `--format json`); butler glyph/stack names use the active Starship palette's `pink` (`format = "[$output](pink)"`). Keep that if you refresh the script from upstream. ` ↑N` is that applied branch's commit count, not upstream-ahead. ` +N` is extra applied stacks. `` is `upstreamState.behind` when nonzero. `` marks a conflicted applied commit or merge base. Status JSON has no ahead, diverged, or uncommitted-file conflict field. The same segment appends file counts (untracked ``, tracked ``, deleted ``) from `uncommittedChanges` plus stack `assignedChanges`, colored from the active palette. `$git_commit`, `$git_state`, `$git_metrics`, and `$git_status` stay disabled in the main prompt so `$all` cannot print workspace noise; `${custom.git_plain}` renders those four, and `${custom.git_ahead_behind}` restores ahead/behind, only when `.git/gitbutler` is absent. Theme switcher sets `palette =` in `starship.toml`.

## Work Guidance

- Match each application's own native config format and conventions.
- Kitty: `cmd+,` is the leader; `gb`, `gd`, and `gt` launch GitButler, gh dash, and tuxedo in vertical splits in the current directory. `cmd+f` and leader `f` search scrollback. Shift+Enter sends kitty CSI u (`ESC [ 13 ; 2 u`) so Empryo can insert a newline. Use explicit `shift+t` for tab selection so it does not override leader `t` (new tab).
- Features take precedence over marginal RAM/CPU optimization — do not remove or degrade existing functionality for small resource wins.
- WezTerm shows native topology by default; while Herdr is foreground, its status bar uses cached `herdr api snapshot` workspace/tab/pane state and falls back cleanly on exit or API failure.

## Verification

No automated checks. Verify by launching the affected app.
